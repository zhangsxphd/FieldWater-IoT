# 数据模型与接入边界

SQLite 使用 `schema_migrations` 管理版本，迁移在事务内执行，兼容初始化阶段已有的 gateways 和 sensors 表，保留已有记录。数据库路径默认位于 `backend/data/fieldwater.sqlite`，禁止指向 LanSense 数据库。请在升级含真实记录的数据库前自行备份并验证恢复。

- gateways：网关标识、通信方式、可选的超时秒数；sensors：独立仪器及其网关关系和用户登记信息。
- telemetry_raw：原始二进制报文、网关与传感器标识、可选设备消息 ID、接收时间、可选设备时间、传输方式、来源与解析状态/错误。
- telemetry_measurements：引用原始记录的测量值、指标、单位、可选设备测量时间、接收时间、质量与来源。
- device_events：通信事件；alarms：实际告警。当前不自动生成告警。

接入层 `ingest` 是内部接口，尚未公开 HTTP、MQTT 或 TCP 接入。它先保存原始报文；解析失败保留错误。设备没有可靠消息 ID 时不去重；有 ID 时同网关、同传感器且原始字节一致才视为重复。同 ID 不同内容会保留冲突报文并标记失败。解析器仅对已经明确请求了寄存器 0000H、数量为一的响应执行读取，不能从响应帧单独推断原始请求。

设备时间未知时 measured_at 保持空，received_at 独立记录；历史查询和排序目前按服务器接收时间。设备状态基于已验证通信事件和网关超时：无事件为待接入；有事件但没有配置超时显示超时未配置；超时后才标记离线。解析失败本身不表示离线；明确的 communication_error 事件显示为通信异常，后续有效通信可恢复状态。在线率以注册传感器总数为分母，空库为 null。多传感器共用网关时，通信状态反映网关通信，并非各仪器健康状态。
