# 真实设备接入安全设计

本文件是下一阶段接入适配器的设计约束，**不代表 HTTP、MQTT 或 TCP 设备接收服务已经实现**。当前服务仅供 `127.0.0.1` 本地开发；未部署 Broker、未开放公网接收、未配置真实网关凭据，也未验证 DTU 的认证能力。用户管理接口与设备接收接口属于不同的身份体系，不能用本地管理接口代替设备接入。

## 一条可审计的接收链路

1. 用户先登记网关，再登记关联的传感器。网关 ID、传感器 ID 是内部标识，不能单独当作认证凭据。仪器串口从站地址只在特定网关和通道内有意义。
2. 根据已核实的 DTU 固件和仪器说明书选择传输适配器，保存硬件型号、固件版本、认证能力、透传格式、串口参数、请求上下文和证据版本。未完成映射时不得自动为未知 ID 创建设备。
3. 适配器先限制连接、报文大小和速率，再识别并验证网关身份；身份由连接认证结果建立，不能信任 JSON 内自报的 gateway_id。网关只能提交已绑定传感器的数据。
4. 保存接收记录及原始字节，记录服务器接收时间、连接来源摘要、适配器与协议配置版本、认证结果、消息 ID 与序列号（设备确实提供时）、设备时间原文。凭据、Authorization Header 和带密钥的 URL 不进入业务日志。
5. 按网关绑定关系、帧完整性与已验证请求上下文解码；分别记录通信、协议、测量值和时间质量。未经认证或身份绑定失败的报文不进入有效测量视图，也不将设备标记为在线。
6. 保留每次投递的证据；重复投递不重复产生测量值，同 ID 不同内容列为冲突。无可靠消息 ID 时保留去重能力限制，不能仅按相同数值或接收时间静默丢弃。
7. 对符合质量条件的测量值建立到原始报文的引用；失败、未知和待核实记录可从接收记录页检查，不以“没有测量值”掩盖解析失败。

数据库写入失败不能返回“已保存”；协议解析失败可以返回“原文已保存、解析失败”，但不能等同于成功测量。若日后使用 MQTT，PUBACK 只表示协议层确认，不保证数据库写入、测量完成或命令执行。

## 身份方式取决于实机能力

| 现场核实结果 | 可评估方案 | 必须补验的条件 |
|---|---|---|
| HTTP 支持 TLS、自定义 Header | 每个网关独立的 Bearer 凭据；若固件支持签名，可评估 HMAC | 证书验证是否真实启用、Header 是否原样发送、重定向是否泄露凭据、密钥轮换与长度限制。 |
| HTTP 支持 TLS，但不支持 Header | 评估固件原生认证或受保护报文中的独立凭据 | 不把密钥放到会被代理、浏览器或访问日志记录的 URL；只有服务器端 JSON 内容不能证明设备具备生成能力。 |
| MQTT 支持 TLS 与独立登录 | 每网关独立用户名/凭据及精确 Topic ACL，必要时评估客户端证书 | 认证结果绑定 gateway_id；禁止通配发布权限；协议版本、QoS、遗嘱、会话、重连与缓存行为均需实机验证。 |
| 仅支持普通 TCP/HTTP 透传或无法验证服务端证书 | 评估受控接入网关、专用网络加安全隧道等转换方案 | 转换端承担认证与 TLS；仍需识别每个现场设备。公网 IP、SIM 号、IMEI、Modbus 地址均不能单独视作秘密凭据。 |
| 不支持消息 ID、可靠时钟或重放保护 | 保留原始投递并记录能力缺口 | 不宣称具备端到端去重或防重放；在此能力下不能将相同测量值认定为重复消息。 |

这些方案尚未选定。当前不生成真实网关密钥、不提供凭据发放端点、不编写未经确认的 DTU 配置指令。

## 凭据的登记、轮换与撤销

未来凭据记录应包含 gateway_id、credential_id、认证类型、创建时间、失效时间、撤销时间、创建人及使用审计，不在设备列表或 API 返回中回显秘密。每个网关拥有独立凭据；一个设备泄露不应要求替换所有网关凭据。

随机 Bearer 凭据可在受控的首次发放时仅显示一次，服务端保存安全摘要；如果采用 HMAC，验证端必须能够取得签名密钥，不能错误地以单向摘要替代，应由受控密钥存储提供。客户端证书方案应保存证书身份和撤销状态，私钥不进入仓库。具体实现与运维方式在传输能力确认后选择。

轮换时明确旧凭据有效截止时间和短暂重叠窗口；撤销立即禁止建立新会话，并评估如何断开旧会话。审计记录凭据标识、认证结果和原因，不记录密钥本身。设备更换和网关转移应保留历史绑定，不通过覆盖旧 ID 将历史数据归给新硬件。

## 时间、重复与重放

- `received_at` 由接收进程的服务器时钟生成；网络报文不能指定它。内部隔离测试可注入受控时间，但网络适配器必须忽略外部同名字段。
- 保留设备时间原文；解析成功后另存标准化时间和质量。缺失、格式无效、明显未来时间、未说明时区以及不可靠时钟均应独立标记。未知设备时间不能被接收时间冒充。
- 数据时效按明确配置的时间基准判断。没有可信测量时间时只能描述“最近接收的有效记录”，不能证明实际测量发生在此刻。断网补传可能刚刚收到历史测量，不应自动当作实时数据。
- 若设备支持可靠消息 ID，按已认证网关的命名空间去重；序列号还须说明重启、回绕和会话语义。重复投递保留接收痕迹并关联首次报文，冲突保留两份原文。
- 若设备支持 HMAC、可信时钟和 nonce，可在原始请求字节上校验签名并在有限窗口内记忆 nonce；允许的时间偏差、断网补传窗口和设备重启机制需要实机确定。单凭消息 ID、TLS 或 CRC 都不能宣称解决重放攻击。

## 四种质量维度

| 维度 | 回答的问题 | 不能推出的结论 |
|---|---|---|
| 通信有效性 | 来源身份、传输和网关绑定是否可信？ | 网关在线不说明所有传感器都有新数据。 |
| 协议有效性 | 长度、CRC、地址、功能码、请求上下文是否匹配？ | CRC 正确不证明来源身份或物理测量准确。 |
| 测量有效性 | 类型、单位、有限数值和已确认的设备规则是否满足？ | 协议可解码不证明仪器已校准；未核实量程、倍率或定义时不能擅自认定数值有效。 |
| 时间有效性 | 设备时间是否存在、格式是否可解释、是否可信？ | 收到数据的时间不是测量时间，也不是时钟已同步的证据。 |

质量规则应具有版本和来源，保留当时判断。异常数值不删除原文；解析或质量规则调整后的重解析应保留旧结果或重解析审计，不能无痕覆盖历史科研数据。雨量累计/时段含义、清零及溢出未确认前，不计算 24 小时雨量、差分雨量或雨强。

## 进入真实联调前的核对项

- 取得实际仪器、铭牌、完整说明书、DTU 固件版本和脱敏配置；确定设备时区、消息 ID、缓存补传与串口透传边界。
- 选择一种有证据支持的认证方式，完成错凭据、撤销、跨网关提交、重复、冲突、截断、大报文、时钟异常和网络恢复测试。
- 使用专门的联调库与独立凭据，明确何时由操作人员确认切换到正式采集。测试向量始终不导入正式库。
- 公网部署另行设计用户认证、授权、TLS、反向代理、备份恢复和监控。本阶段没有执行部署，也没有向真实仪器发送命令。
