# 从设备档案到测量追溯的操作流程

本阶段完成的是本地管理、状态计算、有效测量查询与接收诊断。没有设备、没有通信适配器时，登记档案不会产生在线状态或测量值。没有数据时界面提供下一步入口，不填充演示数值。

## 1. 先建立网关档案

入口：**数据总览 → 登记实际网关**，或 **设备管理 → 网关管理**。

填写网关编号、名称及已确认的厂家、型号、固件、通信方式、位置和备注。通信超时按实际计划上报/心跳机制填写；未知可留空。保存后网关仍为待接入，不能仅因用户填写了 MQTT 就显示 Broker 或设备已经连接。

网关列表显示通信状态、最近有效通信和关联仪器数量。点击关联数量可查看这个网关的仪器；“接收记录”跳转到以该网关过滤的接收诊断。网关通信参数只在此处修改，不通过某个传感器的编辑表单间接修改。

## 2. 为已有网关关联真实仪器

入口：**设备管理 → 传感器管理**。

没有网关时先去登记网关；传感器只能选择已存在的网关。填写仪器编号、类型、名称，以及已确认的厂家、型号、单位、安装位置和备注。数据时效是这台仪器自身测量记录的有效期，与网关通信超时不同；未配置时效不会自动假定某个周期。

列表同时显示“网关通信”和“自身数据状态”。例如网关有一台雨量计上传了有效记录，另一个水位计没有数据，前者可能新鲜而后者仍为无有效数据；网关在线不会把两台仪器一起变为测量正常。

已有仪器的编号、类型和网关关联不能直接修改，避免历史归属发生变化。更换硬件或迁移网关的审计流程尚未实现，不通过覆盖原 ID 处理。档案元数据和数据时效可单独修改。

## 3. 在系统设置检查接入准备情况

入口：**系统设置**。

页面显示当前能力边界，并根据实际档案统计网关通信超时、仪器数据时效的缺项。硬件资料、协议语义与身份认证仍需实机确认；这些项不会因档案填满就自动判为完成。

当前没有“启动 MQTT”“连接真实设备”或“下发写命令”入口。实际接入方式必须依据 DTU 固件与仪器协议选择。设计见 [安全接入](SECURE_INGESTION.md)，资料状态见 [硬件协议](HARDWARE_PROTOCOLS.md)。

## 4. 先检查接收证据，再看有效测量

入口：**接收诊断**，或设备列表里的“接收记录”。

按网关、仪器和处理状态筛选，查看接收时间、来源、处理状态及质量。打开原始记录可检查：

- 原始字节的十六进制表示、网关/仪器标识、消息 ID、来源与传输方式。
- 服务器接收时间与设备时间原文。
- 通信、协议、测量值和时间四种质量以及处理失败原因。
- 重复或冲突记录的首个记录引用。
- 此报文的全部解码结果，包括尚未通过有效测量筛选的结果。

“解析完成”不自动等于有效实测；未验证来源、待核实值、错误时间和历史未复核质量不会进入正常监测或统计。数据仍保留在诊断链路中，不因过滤就丢失。此页当前不执行自动重解析、修改原文或人工将数据一键标成有效。

## 5. 同一查询范围贯穿监测、历史和分析

入口：仪器列表的“监测”，或 **实时监测 / 历史数据 / 数据分析**。

三个页面共用选择逻辑：先选仪器，再选该仪器已有的有效指标和单位，随后选择接收时间范围与排序。设备、指标、单位和范围在服务端先过滤，再分页或截取；不会先取全库最近记录导致低频仪器被挤出视图。

- **实时监测**：显示选定记录、其网关通信状态与自身数据状态，以及按接收时间绘制的趋势。它查看数据库中的有效记录，不会直接触发仪器测量。页面每 30 秒读取后端；这个刷新周期不是仪器采样周期。
- **历史数据**：每页 25 条，按服务器接收时间排序和筛选。每条记录列出设备时间、接收时间、时间质量、来源与原始记录链接。可导出同一筛选范围的 CSV；导出超过服务端限额时需缩小范围。
- **数据分析**：对选定仪器、指标、单位的当前返回有效记录计算最小值、最大值和算术均值。至少两条才计算统计量；说明方法、返回数量及截取限制，并保留每条来源链接。

实时与分析单次视图最多返回 500 条。若匹配记录更多，界面明确提示当前视图是截取结果；统计不宣称覆盖完整时间范围。均值不是时间加权，读数不自动等于区间总量。雨量累计/时段语义未核实时不计算 24 小时雨量、跨记录差分或雨强。

曲线横轴是服务器接收时间，线段只辅助查看已收到记录，不填补缺失观测。设备时间缺失的记录保持 `measured_at = null`，界面分别标记；后端时效此时回退到接收时间，不证明设备在接收时刚刚测量。

## 6. 从测量返回原始报文

监测、历史和分析的记录表内点击“查看 #编号”，进入 **接收诊断** 对应原始记录。复核原文、解析结果与四种质量后，可返回该仪器的监测入口继续查询。这条路径让统计与可视化始终能回到原始接收证据，而不是只展示孤立数字。

## 7. 告警和诊断分开

**告警管理**只展示已有告警，自动规则目前尚未启用。空告警列表不表示网关在线、测量有效或设备正常。实际接收失败、数据过期、身份拒绝和解析异常应从设备状态及接收诊断检查，不自动制造告警记录来填充页面。

后续若加入告警规则，需要明确条件、持续时间、恢复、确认和审计流程，再由实际事件触发。当前没有发送通知或操作真实设备的逻辑。

## 8. 空、加载、错误与待核实

- **未登记**：总览引导用户先登记网关和仪器，设备数量按数据库实际计数；无网关时在线率为 `—`。
- **已登记无通信**：网关待接入，仪器无有效数据；不能显示离线或 0 测量值。
- **收到原文但无有效测量**：可转到接收诊断查看原因，不用“空图表”掩盖失败记录。
- **加载中**：独立加载提示，暂不把未知数据写成 0。
- **请求失败**：独立错误提示和重新加载入口，不能等同于没有数据。
- **资料未核实**：保留空配置或显式未核实状态，不替用户补造型号、单位、周期或协议。

本阶段不提供生产用户登录、真实设备认证、通信接收服务或自动规则告警；不能因为导航、档案和查询已经连通就把硬件接入标为完成。
